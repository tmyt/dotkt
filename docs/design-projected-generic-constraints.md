# Constraint witnesses for Kotlin star projections and F-bounds

**Status and scope.** Proposed replacement for the distributed witness decisions introduced or extended in [#1804](https://github.com/tmyt/dotkt/pull/1804). [#1816](https://github.com/tmyt/dotkt/pull/1816) fixed the override-marker crash; [#1818](https://github.com/tmyt/dotkt/pull/1818) landed the physical-application boundary and corrected late declaration selection. Both are the starting point, not work to repeat. The target is one declaration-owned rule in `bir2cir` for constructors, calls, forwarding and separate compilation. The observable contract is [DotKt semantics §2](dotkt-semantics.md#2-generics-are-reified--nullable-sensitive-uses-carry-a-separate-witness), not the current sequence of implementation branches.

**設計判断の要約。** 優先するのは、Kotlin 本来の型引数と制約で書けることと、Kotlin から既存の CLR API をその契約どおりに呼び出し・継承・実装できることである。`Holder<Leaf<*>>` は異なる `Leaf` インスタンスをコピーせずに格納する。Kotlin 側の宣言は同じ値のクラス制約とインターフェース制約を別スロットで満たせるが、既存の CLR 宣言の一つの型引数を二つに分けることはできない。別 DLL から見てもこの規則と Kotlin の宣言は変わらない。C# からの見た目を整えるために別の意味論や二つ目の override 点を作らない。

## What #1804 tells us

The reported failures include ordinary Kotlin with a concrete type argument. `Queue<FrameAwaiter<Long>>` and `pass(Box(3))` both reached the CLR with a value-view interface in a position requiring a subclass. The presence of a literal `*` or a recursive bound is therefore a poor trigger for a fix. The relevant question is what the **selected declaration** requires at that **use**. [Class construction #1668](https://github.com/tmyt/dotkt/issues/1668) and [method construction #1732](https://github.com/tmyt/dotkt/issues/1732).

| Evidence from #1804 | Contract the next implementation must express |

These were changes made during development of #1804. A subsequent released regression supplies independent evidence about the boundary. In the Compose iterator, an override marker contained three Kotlin arguments while the physical owner had nine slots. The executable receiver and the override marker were separate fields of the same call. The marker entered the physical constraint solver. An arity check can expose this error, but cannot detect a permutation of equally long frames. ## Worked example and choice of representation

```kotlin
open class Root
interface Mark
class Leaf<T>(val item: T) : Root(), Mark
class Holder<A> where A : Root, A : Mark { var item: A? = null }

val holder = Holder<Leaf<*>>()
val first = Leaf(1)
val second = Leaf("two")
fun useHolder() {
    holder.item = first
    check(holder.item === first)
    holder.item = second
    check(holder.item === second)
}
```

Both assignments store the original object. Every `Leaf<T>` is a `Root` and implements `Mark`. The declaration-owned interface used to store an arbitrary `Leaf<*>` cannot derive from the CLR class `Root`. Conversely, `Root` need not implement `Mark`. Closing the exact holder with the first operand's runtime type would also make its type depend on which object was stored first.

A baseline check with the local `DotKt.Sdk` 0.9.30 package compiled the four declarations above into a library. A separate Kotlin consumer compiled against its stripped reference assembly alone and passed both identity checks with the runtime DLL. A second consumer attempted `Holder<OnlyRoot>()` with `class OnlyRoot : Root()`. Kotlin type checking rejected it because the imported declaration also requires `Mark`.

For a Kotlin-generated holder, select its projected implementation and supply a class witness and an interface witness for the **same value**. The primary slot can use `Root` and the extra slot can use `Mark`. Other ordinary, nullable or storage companions follow the declaration's recorded layout. Reads through either proof must operate on the one stored object. If all admissible leaves instead inherit `Mid : Root(), Mark`, `Mid` is a possible single witness wherever the use permits that widening.

For a native base `NativeBase<A> where A : Root, Mark`, one CLR argument must discharge the conjunction. A shared `Mid : Root(), Mark` works; `Root` and a separate interface witness do not. An invariant native interface `IStore<A> where A : Mark` can instead use a single admissible storage/interface witness: both its read and its write must use that *same* closed `IStore` slot. It is the impossible native **construction** that fails at compile time, not the Kotlin generic declaration or an unrelated slot. [Positive native read/write and base cases](../tests/roundtrip/consumer/ConstrainedNullableBoundTests.kt), [native-base negative](../tests/compile-fail/ProjectedNativeBase.kt) and [native-interface negative](../tests/compile-fail/ProjectedNativeInterface.kt).

When a member of `Wrapper<A>` constructs a type that needs `A` in one native slot, constructing the wrapper must satisfy that requirement too. This holds even if the member is never called: after construction, a separately compiled caller holding only `Wrapper<*>` can invoke it. A shared class satisfying both bounds is sufficient; two independent witnesses are not. A holder that only stores the Kotlin value has no such requirement. See the [forwarded construction test](../tests/compile-fail/ForwardedNativeBase.kt).

A self-bound adds a separate obligation. Consider `Node<N : Node<N>>` and `Concrete : Node<Concrete>`. For the source argument `Concrete`, substituting into the bound gives `Node<Concrete>`. The selected physical base and its companion mapping supply the corresponding CLR edge. For `Node<*>`, opening a value gives a fresh hidden `N` with its own recursive bound. Forwarding that capture through a helper preserves the identity of `N`. Opening another `Node<*>` introduces another capture. A shared value carrier can store both, while a call requiring the first `N` still needs evidence for that particular capture. This also explains why an ordinary-to-nullable companion edge and a source `B : A` edge require different treatment. [Self-bound producer](../tests/roundtrip/producer/NullableSelfBounds.kt).

Retain all authored bounds for Kotlin type checking, override selection and DLL re-import. Choose the CLR constraint rows from the proofs the emitted declaration must supply. DotKt already represents some dependent bounds such as `R : I<T>` on a compiler-owned type with its nominal carrier. A foreign invariant `I<T>` retains its exact construction, and a self F-bound keeps its recursive argument. An open virtual slot must supply its published proofs even to a subclass compiled later. A demand introduced inside one override belongs to its implementation. Matching the spelling of the Kotlin `where` clause in C# is optional. [Generic bounds](dotkt-semantics.md#2-generics-are-reified--nullable-sensitive-uses-carry-a-separate-witness) and [declaration and implementation frames](dotkt-semantics.md#9c-bis-nullable-carrier-arguments-and-explicit-representation-frames).

Two alternatives would move the cost elsewhere. Using exact closed CLR types for ordinary Kotlin storage would make an unchecked Kotlin view perform a closed CLR cast on a field write. Specializing in the producer for each concrete instantiation would need to handle type arguments and overrides introduced later by separately compiled consumers. The existing carrier and generated entry cover those uses. The cost worth addressing is that a representation decision currently has to be reproduced at multiple call sites.

### When a callable needs a second CLR entry

For a Kotlin-owned virtual method that needs separate witnesses, use one projected virtual method as the override point. In #1804's `MarkedSelector.selectMarked`, a Kotlin caller writes `selector.selectMarked(first, last)`, and a Kotlin subclass overrides it with one type parameter `A` and its two bounds. Both concrete and projected calls can reach that same method. A concrete type satisfying both bounds can fill both witness positions. A projected caller can pass separate proofs. The compiler supplies those arguments, including when the caller is compiled in another module. [Kotlin declarations](../tests/roundtrip/producer/ConstrainedNullableBound.kt) and [Kotlin calls and overrides](../tests/roundtrip/consumer/ConstrainedNullableBoundTests.kt).

When Kotlin overrides the imported `MarkedStreamReceiver.SourceRef<T>`, the CLR declaration fixes the generic arity, joint constraints and `ref int` parameter. A CLR call through that slot must reach the Kotlin override. Conversely, Kotlin's `super.SourceRef<A>(value, byref(n))` must reach the native base implementation and update the original `n`. These are requirements of Kotlin-to-CLR interop. A helper used inside the Kotlin body can have compiler-chosen witness parameters. [Native declaration](../tests/roundtrip/generic-value-interop/NativeBoxApi.cs) and [Kotlin subclass](../tests/roundtrip/consumer/ConstrainedNullableBoundTests.kt).

Keep #1804's documented source-named forwarding entry and its **single** overridable target. A Kotlin-generated carrier may itself require the exact interface slot; that slot must forward to the same implementation. A future projected-only public ABI might be reasonable for Kotlin, but removing the forwarder or creating that new ABI is not required to replace the decision logic. [Current forwarding implementation](../toolchain/bir2cir/Lowering/Generics/FBoundStarProjectionErasure/ProjectedCallableEntries.cs) and [C# forwarding fixture](../tests/roundtrip/generic-value-interop/NativeBoxApi.cs).

## Who owns each decision

| Data or operation | Authority and lifetime |
|---|---|
| Kotlin declaration identity, override binding, authored bounds, projection and lexical variables | `kotc` supplies the Kotlin facts in BIR. The declaration-binding path retains them for source substitution and metadata. A semantic override edge selects a declaration. An executable MethodImpl gets its own instantiated declaring owner. |
| Ordered primary CLR slots and their constraints | The selected local physical declaration in its producing phase, or the selected referenced TypeDef/MethodDef. Slot roles come from the recorded representation mapping. Actual CLR constraint rows come from the physical declaration, including the shipped runtime twin when applicable. |
| Available physical entries | The `bir2cir` producer declares the class, callable or factory entries, their slot mappings and their contracts. Another DotKt DLL remains Kotlin-owned: consume its published plan. A foreign CLR declaration fixes its own entry; crossing a DLL boundary alone does not make a Kotlin declaration foreign. |
| A particular application | The binder for the construction or call selects an available entry, applies the lexical substitution, and hands the resulting target, ordered arguments and operand requirements to lowering. A synthesized call receives its own binding at creation. |
| Emitted code and metadata | `ilemit` emits the resolved CIR. The reference-assembly path keeps declaration signatures, constraints and Kotlin metadata when stripping bodies. `dll2klib` restores the Kotlin declaration and source bounds for a separate compilation. |

### Declaration and application records

A **declaration plan** describes the physical entries a declaration provides. Before admitting an entry, prove that its open CLR definition is valid for **every instantiation its own formals admit**, even if no caller in this module constructs it. For example, moving `Mark` off a primary `A : Root, Mark` while leaving `NativeBase<A>` on the TypeDef produces an invalid open base. Retain the required joint constraint on the argument used by that base. Select a legal entry at each use; a successful `Slot<Concrete>` cannot certify the open definition. A **bound application** records the result for one use of one admitted entry. Both records are lowering data, not new Kotlin types.

| Declaration plan | Bound application |
|---|---|
| Source declaration identity where applicable, physical identities of the available implementations, factories and forwarders, and the target of each dispatch or forwarding edge | Selected entry handle, closed declaring owner (including for inherited members), lexical owner and method substitutions |
| Ordered physical formals and special constraints, the origin and representation role of each primary slot, and captured/enclosing positions | Actuals already ordered for this entry, with source/capture correspondence retained where proof depends on it |
| For each extra slot, its owning primary slot, the required interface/bound occurrence and any requirement that must remain on the primary slot for a native supertype | Chosen primary and extra arguments, evidence for the required uses, and any operand or typed adapter the selected operation needs |

Use a local declaration binding or a reference-scoped physical identity. A metadata token is meaningful within its module. For a synthesized callable whose representation roles originate on a source method, its producer records how those roles map to the synthesized formals. The method's actual CLR bounds still come from its selected entry. For an inherited member, close the declaring ancestor along the selected inheritance path before substituting its owner variables. Receiver type arguments may be in a different order or belong to a different declaration. [Physical reference parameters](../toolchain/bir2cir/Metadata/ReferenceMetadataIndex/ReferenceMetadataIndex.PhysicalParameterFacts.cs) and [inner application mappings](../toolchain/bir2cir/Lowering/Generics/InnerApplicationFrames.cs).

Use #1818's `PhysicalWitnessApplication` as the starting point for checking **one candidate entry**. It pairs that declaration's formals, layout and supplied arguments before checking; the immutable **bound application** is the output after checking. A generic type walker can rewrite permitted nested declaration types inside an override marker, but cannot submit that marker as a candidate. The call's executable owner and the selected MethodImpl are separate consumers.

Keep three argument lists distinct: **source** arguments, **primary physical** arguments in their producer's representation order, and **entry** arguments after checking the selected entry's primary and extra slots. Close source to primary once with `NullableRepresentationFrame.Close` and the inner/capture mapping. Borrow a materialized list directly only for its own layout; a different entry uses its producer's correspondence, even at equal arity. Its constraint on a primary companion may require a forwarded proof there as well as proofs in appended slots. This is not another source-to-primary expansion. A finished entry is consumed as-is. Arity checks consistency, never which list this is. A semantic override marker has no physical binding operation, including for its nested types.

At the solver boundary `candidate.Slot(i)` supplies the formal, actual, role and binder together. Read siblings through the same candidate; remove the independently supplied argument and free-form scope string. A method application carries the closed owner separately, so CLR `!0` and `!!0` can both occur in one bound. If primary CLR positions are `[ordinary(B), ordinary(A), nullable(A)]`, source `A` maps to position 1 or 2, never 0. Likewise, an equal-length permutation is not an identity mapping. [Nullable representation frame](../toolchain/bir-common/NullableRepresentationFrame.cs) and [#1818's projection context](https://github.com/tmyt/dotkt/blob/d4179d5faf5b3a1c66b95605f2fcb5d12c8de658/toolchain/bir2cir/Lowering/Generics/FBoundStarProjectionErasure/FBoundStarProjectionErasure.ProjectionContext.cs#L150-L209).

The intended call sequence is illustrated below. The names are pseudocode. A binding owns its ordered argument vector, so callers cannot ask about slot 1 while supplying slot 0's candidate.

```text
override edge       → retain selected Kotlin declaration and source owner
physical call site  → start from the source-selected member on its closed declaring owner
                     → obtain primary arguments from the source or materialized binding
                     → check each permitted entry against its own formals and this use
                     → commit one target, ordered actuals, dispatch and operand operations
new inner instance  → bind the selected constructor and actual outer operand
                     → apply its constructor/factory plan in the same way
```

Kotlin owns [type capture](https://kotlinlang.org/spec/type-system.html#type-capturing); traversing a nested type is not another opening. In particular, [`birTypeProjection`](../toolchain/kotc/src/main/kotlin/kotc/backend/BirEmitterTypes.kt) emits the underlying projection, not the IR capture object's identity. Track a physical proof through the **selected operand/binder and its explicit substitution**: forwarding one opening preserves it, independent openings do not share it. Neither the spelling `*`, a nested path alone, nor equal CLR storage types establish this relation. If a valid Kotlin use needs a correlation not present on those edges, carry that specific semantic relation from `kotc` in BIR; do not infer it in `bir2cir` or ask `kotc` to choose a CLR witness.

### Closing and checking a use

1. **Classify the use before looking for witnesses.** An ordinary value uses its storage representation; an `is` or cast uses its Kotlin classifier rule. Neither requests a proof just because its type looks constructed. A TypeSpec, MethodSpec, base/interface or MethodImpl needs physical arguments for its selected declaration. Array-element representation slots and reified classifier operands serve different operations; an interface proof is not a substitute for either.
2. **Build one substitution environment.** A variable is identified by its declaring binder and position. Expressions in actual arguments belong to the caller. References in constraints belong to the callee. Keep capture identity for the duration of the application. Nullable and storage companions of the same source parameter have a recorded relation. Two independently opened `Leaf<*>` values can have the same physical storage type and different hidden types.
3. **Close connected constraints together.** Keep `B : A` directed: a fixed `B` restricts which `A` may be chosen; it does not equate them. The structurally equal actuals used by `SharedClassWitness` do not prove capture identity. Substitute `B` into `A : I<B>` and the **same** `X` into `X : Rec<X>`. Draw candidates from the actuals, declared caller proofs, their applicable nominal supertypes and the entry's declared facets under substitution. Test the finite choices for one connected group; an early preference is provisional until its dependent rows fit. Check cyclic rows under one simultaneous substitution. A back-edge names its binder; it neither proves assignability nor generates ever larger candidates such as `Rec<Rec<…>>`. Memoize by entry and substitution within this use; independent slots need no Cartesian product. [Existing self-bound and companion handling](../toolchain/bir2cir/Lowering/Generics/OwnerConstrainedMethodLowering/OwnerConstrainedMethodLowering.cs).
4. **Check both sides of a candidate.** (a) Does this operation supply the proposed type for this source argument? Static evidence for a hidden argument must cover *all* permitted values, not just today's operand. (b) Does that type satisfy every substituted CLR bound and special constraint on this entry, with CLR variance? For an open caller variable use what its own declaration guarantees. Meeting (b) alone could choose an unrelated class deriving from `Root` and implementing `Mark`; meeting (a) alone could put the storage interface in a slot requiring `Root`. An unchecked Kotlin annotation is not proof of an exact construction. An invariant native `I<T>` or `ref T` needs its actual construction or pointee, not a different one with equally legal bounds. [CLI generic constraints, ECMA-335 II.9.11](https://ecma-international.org/wp-content/uploads/ECMA-335_6th_edition_june_2012.pdf#page=163).
5. **Commit the operation, not just the witness vector.** Try only entries published for the already-selected declaration; failure for one does not change overload or contaminate another entry's arguments. Record the selected entry, complete ordered vector, dispatch kind and operand operations. Preserve Kotlin evaluation order and evaluate each operand once. Only a call already covered by the [runtime intersection ABI](../libraries/stdlib/clr/DotKt/Runtime/CompilerServices/StarProjectionRuntime.kt) may defer specified missing slots to specified evidence operands. It still calls the selected method. Null is not type evidence; a typed address adapter forwards the original location, never a boxed pointer or copy-back. This is not a fallback for an invalid static TypeSpec or permission to use reflection for all calls.

Keep **ordinary use**, **proved static application**, **authorized runtime call**, and **unrepresentable native construction** distinct. Preserve a guaranteed exact argument; for a projected use, forward the designated proof if it discharges the obligation before searching for a common witness. The choice is observable: when the [native peer](../tests/roundtrip/generic-value-interop/NativeBoxApi.cs) returns `typeof(T).Name`, the [consumer](../tests/roundtrip/consumer/ConstrainedNullableBoundTests.kt) expects `ExactStream` even with a `DerivedStream` operand, but `IProjectedMark` for the corresponding interface-only call on a hidden argument. Traversal order, reference metadata order and separate compilation must not change either answer. Missing facts, a stale frame or an incomplete search do not establish native impossibility. They are compiler defects, not new user-program undefined behavior or reasons to reject ordinary Kotlin.

## Carrying the decision through lowering

| Transition | Implementation change |
|---|---|
| Local, referenced and late declarations | Build the plan using the declaration reader for that phase. For a late local type read formals and roles from the same `CurrentPhysicalTypeView` entry, including newly admitted generated types. Keep early source inventories available for their original consumers. A reference reader selects the physical declaration and its producer-recorded role mapping. [Current physical type view](../toolchain/bir2cir/Lowering/Generics/FBoundStarProjectionErasure/FBoundStarProjectionErasure.LateTypes.Source.cs). |
| Class and constructor | Extend `ProjectedClassStorageFrame` so declaration (`Declare`) and application (`Close`) use the same primary/extra slot descriptors. Retain the selected constructor ID, visibility, abstract status and required native supertype bounds. An inner factory takes the actual outer operand once and uses its recorded captured prefix. [Construction binding](../toolchain/bir2cir/Lowering/Generics/FBoundStarProjectionErasure/FBoundStarProjectionErasure.Rewrite.Source.Constructions.cs) and [inner factory](../toolchain/bir2cir/Lowering/Generics/FBoundStarProjectionErasure/FBoundStarProjectionErasure.ProjectedInnerFactory.cs). |
| Method, override and delegate | Give `ProjectedCallableEntries` the selected Kotlin declaration, implementation and any required fixed-signature slots. Virtual calls use the same override chain; `super` calls the selected base implementation directly. A generic invocation can use a MethodSpec. A MethodImpl binds method **definitions** on the appropriately instantiated owner: retain the method's open `!!i`, never put invocation-specific method arguments on the override edge. [Callable entries](../toolchain/bir2cir/Lowering/Generics/FBoundStarProjectionErasure/ProjectedCallableEntries.cs) and [ECMA-335 II.9.10](https://ecma-international.org/wp-content/uploads/ECMA-335_6th_edition_june_2012.pdf#page=162). |
| Generated closure or native call inside a projected body | Remap each used owner/method slot through the capture mapping at the generated declaration's birth. Forward the existing proof when it satisfies the native method's own joint constraints. Preserve lexical access, the actual receiver and the original location, including aliased writes on exceptional exit. Keep the supported typed-adapter path distinct from ordinary foreign-star reflection, whose `object[]` cannot transport managed addresses. [Projected calls](../toolchain/bir2cir/Lowering/Generics/CapturedGenericInvocation.ProjectedStorage.cs) and [address adapters](../toolchain/bir2cir/Lowering/Generics/CapturedGenericInvocation.ProjectedAddresses.cs). |

**Handoff between existing components.** `ProjectedCallableEntries.Bind` currently closes bounds, fills companion arguments, selects a method and updates its member reference. When that binding path does not handle a node, `ProjectStorageCall` examines the selected native method and the lexical slots. Move the target and argument decisions to the bound application. Let these consumers apply its result to their respective graph nodes. The native adapter can still derive its typed invocation signature from the selected MethodDef. Likewise, use the stored proof-slot mapping in `ProjectedConstructorArguments` so selecting a factory consumes the layout that declared it. Remove the parallel calculations as each consumer switches. [Callable binding](../toolchain/bir2cir/Lowering/Generics/FBoundStarProjectionErasure/ProjectedCallableEntries.cs) and [native call binding](../toolchain/bir2cir/Lowering/Generics/CapturedGenericInvocation.ProjectedStorage.cs).

**Phase lifetime.** Demand analysis establishes eligible carriers and operation requirements. Realization authors entries and admits new declarations. For a later target, retain its identity and symbolic slot correspondence, not an obsolete declaration object. Bind layout **and** constraint rows from the same live declaration before producing CIR. Cloning into a new binder rebinds the affected slots; placement remaps a changed enclosing prefix. Admit newly generated nodes at the producing boundary, not by repairing the whole file. Release source graph references at `CompleteRealization`; carry only the published relations needed downstream. A cached proof cannot survive a changed declaration, substitution or capture. `ilemit` encodes the resolved target; it never finishes witness selection. [Current continuation](../toolchain/bir2cir/Lowering/Generics/FBoundStarProjectionErasure/FBoundStarProjectionErasure.Realization.Continuation.cs) and [materialization contracts](bir2cir-phase-contracts.md).

**Separate compilation.** A stripped reference assembly must let `dll2klib` reconstruct one Kotlin declaration with its source name, type parameters, bounds, parameter and return types, and modality (`open`, `abstract` or final). Today the exact forwarder carries the source modality for split virtuals. Keep it; the implementation's extra slots are not Kotlin type parameters. Distinguish the source declaration ID from the physical IDs of the forwarder, implementation and factory. [Roundtrip callable metadata](../toolchain/bir2cir/Metadata/RoundtripMetadata/RoundtripMetadata.Callables.Source.cs) and [DLL-to-KLIB design](design-dll2klib.md).

For binding calls, record each extra slot's physical ordinal, owning primary ordinal and the bound it discharges in that entry's binder. Read actual constraints from the selected TypeDef/MethodDef. A row number or “first interface bound” in a separately emitted image is not a cross-module identity. Reuse declaration IDs, representation/capture frames and physical member references; publish only missing relations. Replace `ProjectedCallableEntries.Find`'s reconstruction from the original formals and `ReferencedConstruction`'s use of `Constraints[0]` with that mapping. Ship its writer, ref-assembly retention and reader together, using the existing reference/runtime identity mapping. Do not infer absent metadata from a generated name, arity, method body or old DLL. [Callable and factory lookup](../toolchain/bir2cir/Lowering/Generics/FBoundStarProjectionErasure/ProjectedCallableEntries.cs) and [reference metadata](../toolchain/bir2cir/Metadata/ReferenceMetadataIndex/ReferenceMetadataIndex.cs).
