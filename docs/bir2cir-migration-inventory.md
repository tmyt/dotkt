# bir2cir Lowering Migration Inventory

Last updated: 2026-06-27

Companion to [design-fir-bir-cir-il.md](design-fir-bir-cir-il.md) and [bir2cir-handoff.md](bir2cir-handoff.md). Generated by a 14-agent inventory workflow (13 per-family classifiers + 1 synthesis) over `ilemit` consumers, `kotc` BIR producers, and the `ExecutableCirDraft` lowering, then re-synthesized under the project's breaking-changes-allowed policy ([[break-for-elegance]]).

## Summary

Across 13 families there are 102 BIR node kinds, but only ~34 are genuine near-term bir2cir lowering targets: 26 BasicLowering + 8 ClrProjection, every one currently passthrough (bir2cir recurses their children but leaves the BIR kind intact for ilemit's legacy emitters). The other 68 are out of scope for clr.* lowering: 25 are stdlib APIs that must LEAVE the compiler (retire, never lower), 21 are pass-through control-flow that need no clr.* node, 17 suspend + 3 inline are explicitly-deferred separate phases, and 2 are diagnostic sentinels. The migration itself is a mechanical, already-proven loop (add a TryLowerPhysical* sibling next to the existing conv/isinst/property/event lowerings, mirror a clr.* case in ilemit, add a deterministic fixture, commit), gated behind three escalating infrastructure investments: a per-method scope/type environment, a same-module member resolver, and a reference-metadata overload resolver. Because nothing has shipped and breaking changes are free, the decisive first move is to flip the default to --native-cir and delete the --compat-bir path up front (native-cir already passes through unmigrated nodes identically, so the byte-for-byte invariant blocks nothing) gated only on verify-native-cir-ilemit.sh going green, then delete each compiler intrinsic outright as its wave lands. Sequencing climbs from the no-infrastructure physical primitives through the env/same-module/reference-metadata resolvers and finishes with delegate/closure construction, with stdlib-retire, suspend, and inline run as parallel non-wave workstreams.

## Migration plan (breaking-changes-aware)

**Milestone 0 — flip up front.** Make `--native-cir` the default and **delete the `--compat-bir` path**. native-cir already passes unmigrated nodes through byte-identically, so the only safety gate is `scripts/verify-native-cir-ilemit.sh` staying green across the fixture corpus — *not* byte-for-byte BIR equality (which is being abandoned). This is low-risk and unblocks deleting each legacy intrinsic as its wave lands.

### Wave 1: Self-contained physical primitives (no env, no metadata) - the cleanest TryLowerPhysical* increments

Kinds: `arrayLen`, `arrayGet`, `arraySet`, `bin`, `un`, `const`, `default`, `nullableOf`, `concat`, `stackAlloc`, `stackGet`, `stackSet`

MILESTONE/PRECONDITION: before this wave, flip the default to --native-cir and DELETE the --compat-bir path - native-cir already passes through every unmigrated node byte-identically, so the only safety gate is verify-native-cir-ilemit.sh staying green, not BIR equality. Each kind here is a pure physical CIL op whose element/result type travels on the node (or needs none): no scope environment and no @Clr/reference lookup. They wrap cleanly because their operand children stay as raw local/this nodes that ilemit still consumes until later waves. Mirror the proven TryLowerPhysicalTypeOp->clr.conv/clr.isinst pattern with a sibling helper + a mirrored ilemit clr.* case; nullableOf is a zero-new-code alias onto the already-shipped clr.nullable.wrap. One TryLowerPhysical*+fixture+commit increment per kind; delete each legacy ilemit case and any retired intrinsic as it lands. Watch the hidden const-null->Nullable<T> coercion (EmitNullableCoerced): lift it to an explicit clr.nullable.null during lowering or it silently regresses Int? literals.

### Wave 2: Composite/constructed physical primitives (still no env/metadata, med risk)

Kinds: `newArray`, `spreadConcat`, `stackAsSpan`, `constrainedCall`

Same no-metadata physical character as wave 1 but more moving parts that each warrant fixtures over their variant shapes: newArray doubles as the object[] builder for varargs/enum-values/String.Format (keep the NeedsBoxToRef value->object boxing inside ilemit so the node stays a pure (elem,elems) construction); spreadConcat assembles a generic List<T> via BCL Add/AddRange/ToArray (TypeBuilderInstantiation .GetMethod hazard when elem is an enclosing generic-function type param); stackAsSpan newobj's a constructed-generic System.Span<T> ref struct via a fixed (void*,int) ctor; constrainedCall is a fixed-target Basic Lowering (System.IComparable<T>::CompareTo via constrained.callvirt + EmitAddr managed pointer) with NO overload/metadata risk. Depends only on wave 1's vocabulary being in place.

### Wave 3: Per-method scope/symbol environment + the locals it unlocks (new infra)

Kinds: `this`, `local`

Shared infrastructure milestone: ExecutableCirDraft is path-only today with no method/class context. Build a per-method local/param CLR-type + slot-kind (arg vs local) environment and current-receiver-type threading, then lower this->clr.this (ldarg.0 + receiver type) and local->clr.local (typed slot, arg-vs-local). Both have a SECOND consume site (Program.cs:EmitAddr, the lvalue/byref address path) that must also move to clr.* before the legacy handling can be deleted. Inline-substitution and coroutine SM-field redirection stay owned by the inline/suspend phases - the plain read is the Basic-Lowering target. This env is the prerequisite for wave 4's byref addr-of.

### Wave 4: Same-module member resolution: field stores, lateinit, byref family (new resolver)

Kinds: `setField`, `lateinitGet`, `byrefOf`, `byrefLoad`, `byrefStore`

Builds on wave 3's env plus a NEW same-module field/member resolver (today's resolved-call path only resolves referenced-assembly symbols; setFieldExpr/staticFieldSet are covered but the same-module setField STATEMENT and lateinit backing fields are not). Unlocks clr.stfld/clr.fieldRef (setField), the guarded field-load clr.lateinitGet, and the byref family which ships as a unit: byrefOf is design-bearing (addr-of local/arg/field/this via ldloca/ldarga/ldflda, plus the deref:false coordination so a ref-returning clr.call keeps its managed pointer instead of dereferencing), byrefLoad/byrefStore are trivial ldobj/stobj over the ref local but only meaningful once byrefOf exists. Carry elem as clr.typeRef explicitly - it is outside TypeSiteAnalyzer's scanned set so generic recursion will not normalize it.

### Wave 5: Reference-metadata overload resolver: physical .NET calls/ctors/fields (ClrProjection)

Kinds: `clrStaticField`, `clrNew`, `clrStatic`, `clrInstance`, `boundClrDelegateNew`, `clrGenericStatic`, `clrGenericInstance`

The heaviest shared dependency: a unified reference-metadata method/ctor/field resolver with real overload resolution (argTypes->exact/arity, generic clrg: owners, inherited interface members, generic-method shape + MakeGenericMethod). Mirror the existing TryLowerPhysicalProperty/Event into TryLowerPhysicalCall/New/StaticField; the consumers already exist (EmitNativeClrCall/NewObj/FieldGet) so ilemit then deletes six legacy reflection cases. Order within the wave by rising risk: clrStaticField (single Unit singleton - or retire as a fixed clr.ldsfld with no lookup) -> clrNew -> clrStatic/clrInstance -> boundClrDelegateNew (new delegate-bind resolved site) -> clrGenericStatic/clrGenericInstance LAST (generic shape resolution + variance + MakeGenericMethod). NB many clrStatic/clrGenericStatic producers are stdlib intrinsics (Math/String.Format/Convert/LINQ/Seq) that exit via the retire workstream, not this projection wave - the node KIND is still legitimate ClrProjection for genuine @Clr calls.

### Wave 6: Delegate and closure construction (same-module lifted methods/closure types)

Kinds: `delegateNew`, `boundDelegateNew`, `delegateInvoke`, `closureNew`

Depends on wave 4's same-module ref encoding PLUS relocating the func:->CLR delegate-type mapping and synthetic-arity delegate synthesis (KFunc`N/KAction`N via TypeBuilder) out of ilemit so bir2cir can mint a clr.typeRef for synthetic delegate arities. Order: delegateNew first (no child exprs, simplest) -> boundDelegateNew (same-module user method, ldftn/ldvirtftn) -> delegateInvoke (its clean callvirt-Invoke clr.delegateInvoke form is correct ONLY after the phase-1 inline lowering removes the inline-lambda-param splice fast path - so this kind is gated on the separate inline phase) -> closureNew LAST (highest risk: current-module synthesized closure TypeBuilder not in the reference index, constructed-generic member re-anchoring via TypeBuilder.GetConstructor/GetMethod on MakeGenericType).

## Cross-cutting risks

- Shared dispatch files: bir2cir/Program.cs (ExecutableCirDraft.LowerNode + TryLowerPhysical*) and ilemit Emitter.Expressions.cs/Emitter.Statements.cs are touched by nearly every wave - commit each kind incrementally or the changes entangle into an unsplittable diff.
- Generic/variance overload resolution is the gating risk for wave 5: clrGeneric*/clrNew/clrInstance need real shape-based overload selection, MakeGenericMethod, and TypeBuilderInstantiation re-anchoring when T is an enclosing generic-function type param (the .GetMethod hazard) - easy to get subtly wrong; build and stress the resolver before moving clrGeneric*.
- Second consume site EmitAddr: this/local/byrefOf are also consumed in Program.cs:EmitAddr (lvalue/byref/constrained address path); ilemit's legacy handling cannot be deleted until BOTH sites consume the clr.* form.
- Hidden ilemit-resident policies that a naive wrap silently drops and regresses: const-null->Nullable<T> and cond/return branch Nullable<T> coercion (EmitNullableCoerced), value-type boxing in newArray/concat, and the protected-region `leave` for return-in-try - each must be lifted to an explicit node or deliberately kept in the consumer.
- Same-module vs reference-assembly split: the current resolver only resolves referenced-assembly symbols, so setField/lateinitGet/delegateNew/boundDelegateNew/closureNew (current-module lifted methods/fields/closure TypeBuilders) cannot ride the reference-only path - a new same-module member-ref encoding is a hard prerequisite, do not attempt them early.
- Stdlib-retire ordering and dual representation: collection factories (listNew/setNew/mapNew) must retire together with COLLECTION_MEMBER/COLLECTION_OPS so the physical identity 'kotlin lists ARE BCL List<T>' stays coherent; associate*/groupBy/withIndex stdlib actuals must preserve LinkedHashMap/IndexedValue insertion order or map-iterating fixtures go nondeterministic.
- Nondeterministic fixtures: never print raw pointers/addresses (stack family emits intentionally-unverifiable IL), object hashcodes, or HashSet/Dictionary iteration order; host-convention primitive formatting (True/4 not true/4.0) is normalized by the differential harness, so fixtures must rely on that normalization.
- delegateInvoke is entangled with the inline phase (its inline-splice fast path is phase-1 inline lowering); its clean clr.delegateInvoke form is only correct after the inline phase lands - do not migrate it before then.
- Orphan/dead-code and WIP churn: several ilemit cases are already dead (listGet/listSet/mapGet/mapSet/mapSize, the linq/associate set, tupleNew/tupleItem) - delete, do not migrate; and the uncommitted tree is mid-retirement of coroutine-context intrinsics (coContext producer already removed), so reconcile producer state before designing the suspend CIR.
- The flip gate: 'delete --compat-bir / default to --native-cir' must be gated on verify-native-cir-ilemit.sh being green across the full fixture corpus, not on byte-for-byte BIR equality (which is being abandoned); because native-cir already passes through unmigrated nodes the flip is low-risk and should happen up front, but the harness is the real safety net.
